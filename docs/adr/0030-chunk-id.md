# ADR-0030: チャンクIDを「法令の版 + 法令内の連番」で生成する

## Context and Problem Statement

ベクトルDBに投入する各チャンクには一意なIDが必要である。
当初は意味が読めるIDを目指し、以下の要素を連結する方式を試した。

```
law_revision_id : provision : article_num : paragraph_num : item_num : split_index
```

現行版 706,024 チャンクに対して適用したところ、**一意なIDは 490,518 件**にとどまり、
21.5 万件が重複した。重複の上位は以下のとおり。

```
1132  324M50000001013_20260423_508M60000010004:附則::1::
 676  325AC0000000226_20261001_507AC0000000070:附則:1:::
 454  336M50000100001_20261001_508M60000100107:附則::1::
```

原因は**附則が区別できていない**ことであった。1法令に附則は何百個も存在し
（地方税法は 939 個）、どの附則にも第1条・第1項がある。
`provision` が「附則」としか入っていないため、何番目の附則かを表現できていない。

`amend_law_num`（改正法令番号）を要素に加えたところ重複は大幅に減ったが、ゼロにはならなかった。

```
9  325M50080000018_...:附則:令和八年七月三〇日総務省令第九五号:4:1:2:
2  429M60000008079_...:本則::18:1:17:
2  325M50080000018_...:本則::24:36::
```

残った重複の原因は2つ。

* **同じ改正法令番号の附則が複数存在する**（9件）
* **同じ項に同じ `Num` の号が複数存在する**。
  実例として `429M60000008079`（地方独立行政法人法別表及び地方独立行政法人法施行令
  第五条第一項の総務省令で定める事務を定める省令）第18条第1項の号番号は
  `[..., '16', '17', '17', '18', '19']` となっており、第17号が2つある

条番号・項番号・号番号の組み合わせでは一意性を保証できない。

## Decision Drivers

* IDは一意でなければならない（重複すると Chroma で上書きが起きる）
* 再実行時に同じIDが生成されること（再現性）
* 法令単位での削除・更新ができること

## Considered Options

1. 条番号・項番号・号番号などを連結する（意味が読める）
2. UUID（`uuid4`）を生成する
3. テキストのハッシュを用いる
4. 法令の版 + 法令内の連番

## Decision Outcome

Chosen option: "法令の版 + 法令内の連番", because
選択肢1は上記のとおり一意性を保証できない。

選択肢2（UUID）は一意性こそ保証されるが、**実行のたびに異なる値が生成される**。
同じチャンクを入れ直したときに前回と対応付けができず、
更新のたびに全削除が必要になる。再現性がない。

選択肢3（テキストのハッシュ）は、「この省令は、公布の日から施行する」のような
同一文言のチャンクが大量に存在するため衝突する。

選択肢4は、`get_chunks_with_meta` が1法令分のチャンクを返す単位であることを利用し、
その戻り値に対して連番を振る。**法令ごとに 0 から振り直す**ため、
ある法令を処理し直しても他の法令のIDに影響しない。

```
335M50000400013_20260521_508M60000400043#0
335M50000400013_20260521_508M60000400043#1
```

現行版 706,024 チャンクで一意性を確認済み（重複0件）。

IDから条番号等を読めなくなるが、**すべてメタデータに保持している**ため実害はない。
IDは識別子に徹し、意味の表現はメタデータが担う。

### Consequences

* Good: 一意性が保証される（706,024件で実測確認）
* Good: 同じ入力に対して同じIDが生成され、再現性がある
* Good: 法令の版がIDに含まれるため、法令単位での削除・更新が可能
* Good: IDが短く、組み立ても単純
* Bad: IDから条番号や項番号を読み取れない。デバッグ時はメタデータを参照する必要がある
* Bad: 法令が改正されて条が追加・削除されると、同一の条でも連番がずれる。
  差分更新では法令単位でチャンクを作り直す設計のため実害はないが、
  「変わった条だけ更新する」方式を採る場合は再検討が必要
* Bad: 同じ項に同じ `Num` の号が存在する理由は未調査。
  枝番の表現がXML上で失われている可能性があり、出典表示に影響しうる
