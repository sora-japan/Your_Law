# ADR-0006: 本則が抄録の法令を除外せず、回答時に注記で示す

## Context and Problem Statement

法令標準XMLスキーマの `Extract` 属性は「抄録（一部を抜粋して収録）している場合に `true`」
と定義されており、`MainProvision` と `SupplProvision` に付与される。

全法令を対象に調査したところ、タグ別の内訳は以下であった。

| タグ | Extract="true" の件数 |
|---|---|
| SupplProvision | 239,380 |
| MainProvision | 292 |

`SupplProvision` の239,380件は、改正法の附則から施行期日・経過措置の部分だけを
抜粋して収録したもので、附則361,881件の約66%にあたる。これは通常の収録方式である。

`MainProvision` の292件（全法令10,702件の2.7%）は、**法令本体が全文収録されていない**。
この場合、収録されていない条文に重要な規定が存在する可能性がある。

## Decision Drivers

* 関係する法令を取りこぼさないこと
* 利用者が、参照している情報の限界を認識できること

## Considered Options

1. 本則が抄録の法令（292件）を検索対象から除外する
2. 何も処理せず、通常の法令と同じように扱う
3. 除外せずメタデータにフラグを持たせ、回答時に注記を添える

## Decision Outcome

Chosen option: "除外せずメタデータにフラグを持たせ、回答時に注記を添える", because
選択肢1では、実際に関係する法令を利用者に提示できなくなり、取りこぼしとなる。
選択肢2では、収録されていない条文の存在を利用者が認識できず、
「この法令の全文を確認した」という誤った前提で判断されるおそれがある。

チャンクのメタデータに抄録フラグを保持し、該当法令を根拠として提示する際に
「この法令は本則の一部のみが収録されています。全文はe-Gov法令検索でご確認ください」
という注記を添える。

`SupplProvision` の抄録については、改正法からの抜粋という正常な収録方式であるため、
特別な処理を行わない。

### Consequences

* Good: 関係する法令を取りこぼさない
* Good: 情報の限界を明示することで、利用者が自分で確認する判断ができる
* Good: 収録範囲の限界が利用者に伝わり、必要なら原典を確認する判断ができる
* Bad: 回答に注記が増え、出力が冗長になる
* Bad: 抄録フラグをチャンク単位で保持するため、メタデータの項目が1つ増える
