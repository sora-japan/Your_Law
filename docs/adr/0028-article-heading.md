# ADR-0028: 分割されたチャンクの冒頭に条見出しと条番号を付与する

## Context and Problem Statement

チャンク分割の実装後、閾値を変えて生成される総文字数を測定したところ、
**閾値によって総文字数が約10%変動する**ことが判明した。

| 閾値 | チャンク総数 | 総文字数 |
|---|---|---|
| 200 | 2,524,997 | 263,533,488 |
| 500 | 1,540,774 | 278,710,934 |
| 1,000 | 1,099,766 | 289,184,599 |
| 2,000 | 841,815 | 293,924,098 |

（全10,702ファイル・本則のみ。重複版を含む）

閾値が小さいほど文字数が減る。分割の仕方が変わるだけで元のテキスト量は
変わらないはずであり、どこかで文字が失われていることになる。

原因を特定するため、閾値1,000で項以下に分割された条について、
**条全体のテキスト**と**生成されたチャンクを連結したテキスト**を
`difflib.SequenceMatcher` で比較した。

対象法令（商標法施行規則、`335M50000400013`）で差分が出たのは5条。

| 条 | 条全体 | チャンク合計 | 差 |
|---|---|---|---|
| 2 | 1,396 | 1,385 | 11 |
| 7_2 | 1,191 | 1,151 | 40 |
| 16 | 1,531 | 1,516 | 15 |
| 18 | 1,562 | 1,546 | 16 |
| 22 | 8,216 | 8,198 | 18 |

第2条と第7条の2について `get_opcodes()` で差分の中身を確認した結果、
いずれも `delete` が1件のみであった。

```
delete '（願書の様式等）第二条' → ''
delete '（パリ条約による優先権等の主張の規定の適用を受けようとする場合の手続）第七条の二' → ''
```

**失われていたのは `ArticleCaption`（条見出し）と `ArticleTitle`（条番号）のみで、
本文の欠落はなかった。** 差が11〜40文字とばらついていたのは、条見出しの長さの違いによる。

原因は構造にある。条のテキストは `extract_text(Article)` が配下すべてを取るため
条見出しと条番号を含むが、項のテキストは `extract_text(Paragraph)` であり、
親要素である `ArticleCaption` / `ArticleTitle` を含まない。
**階層を降りるたびに、親のラベルが脱落する。**

結果として、分割されたチャンクは以下の状態になっていた。

* `level: 'Article'` のチャンク → 条見出しを含む
* `level: 'Paragraph'` / `'Item'` / `'Split'` のチャンク → 含まない

同一法令の中でチャンクの形式が統一されておらず、
分割されたチャンクは単体では何についての規定か判別できない。

なお `ArticleCaption` を持たない条は 79,824 件（全 551,320 条の 14.5%）存在する
（実測。`Article` と `ArticleCaption` の出現数の差 79,824 とも一致）。

## Decision Drivers

* チャンクが単体で、何についての規定か判別できること
* 出典表示に条見出しが使えること
* 同一法令内でチャンクの形式が統一されていること
* 条見出しは他の要素と重複しない唯一の情報源であること

## Considered Options

1. 何もしない（失われたままにする）
2. メタデータに `article_caption` として保持し、テキストには含めない
3. 分割されたチャンクのテキスト冒頭に、条見出しと条番号を付与する

## Decision Outcome

Chosen option: "分割されたチャンクのテキスト冒頭に、条見出しと条番号を付与する", because
選択肢1では、分割されたチャンクが単体で文脈を持たない。
「願書の様式について知りたい」という質問に対し、該当する項が検索で引けない。

選択肢2は出典表示には足りるが、検索には寄与しない。
条見出しは「（願書の様式等）」のように条の主題を端的に表しており、
検索の手がかりとして有用と判断した。

選択肢3を採ることで、`level: 'Article'` のチャンクと形式が統一される。
条のチャンクには既に含まれているため、**分割されたチャンクにのみ付与**し、
二重付与を避ける。

ADR-0007（目次をチャンク化しない）との整合も取れている。
目次を除外した理由は「章名は本文側の `ChapterTitle` にも存在し重複するため」であった。
条見出しは逆に、分割されたチャンクのどこにも存在しない唯一の情報源であり、
同じ基準を適用すれば付与すべきものとなる。

付与の形式は `ArticleCaption` + `ArticleTitle` の順とする。
条全体のテキストがこの順序（「（申請書）第一条…」）であり、それに揃える。
`ArticleCaption` を持たない条では条番号のみを付与する。

**句点分割（`level: 'Split'`）では、分割前のテキストに見出しを付与する。**
その結果、見出しが付くのは先頭の断片のみとなる。全断片に付与すると、
文の途中から始まる断片に見出しが繰り返し現れ、不自然なテキストになるため。

### 比較実験を行わない判断

「条見出しをテキストに含めた場合と含めない場合」の検索精度比較は行わない。
分割されたチャンクには条見出しが存在せず、単体では何についての規定か判別できないため、
含めない状態は出典表示の観点からも成立しないと判断した。
残り期間の制約も考慮している。

### Consequences

* Good: 全チャンクが同一形式となり、単体で何条の規定か判別できる
* Good: 検索時に条見出しが手がかりとして機能する
* Good: 出典表示に条見出しを利用できる
* Good: 閾値による総文字数の変動が解消される（各チャンクに見出しが復元されるため）
* Bad: 見出しの分だけチャンクの文字数が増え、閾値の実効値がわずかに下がる
* Bad: 句点分割の2番目以降の断片には見出しが付かず、単体では文脈を持たない
  → メタデータの `article_num` と `split_index` から同一条の他チャンクを取得できる
* Bad: 条見出しを持たない条が 14.5% あり、それらは条番号のみとなる。
  チャンク間で情報量に差が生じる
* Bad: 比較実験を行っていないため、条見出しの付与が検索精度に
  実際に寄与するかは未検証である
