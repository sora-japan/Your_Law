# ADR-0055: 号のチャンクに項の柱書を前置し、分割後の断片にも前置きを付ける

## Context and Problem Statement

`chunk_splitting.py` を読み直したところ、チャンクの本文が2箇所で落ちていた。

**1. 項の柱書。** `paragraph_chunking` は、項が閾値を超えていて号を持つとき、号だけを
チャンクにしていた。修正前の41〜61行目で `paragraph` から読んでいるのは `Num` 属性と
子の `Item` だけで、項そのものの文（`ParagraphSentence`、柱書）をどこにも出していない。

号は柱書に続けて読む前提で書かれている。柱書が「どういう場合にどうなるか」を決め、
号はそれに該当するものを並べる。たとえば柱書で「次の各号のいずれかに該当する者は
登録を受けることができない」と定め、号で該当する者を列挙する形が多い（この文面は
形を示すための例で、実在の条文の引用ではない）。**号だけを読むと列挙されたものの
説明でしかなく、それがどう扱われるのかは柱書が決めている。**

**2. 句点分割後の条見出し。** `split_by_threshold` に渡すテキストに条見出しを足してから
分割していたため、条見出しが入るのは `split_index` が 0 のチャンクだけだった。

### 条から項に降りるときは落ちていない

条が自分で持つテキストは見出しと付記で、本文はすべて `Paragraph` の中にある
（`Article` の子要素は `<ArticleCaption>` | `<ArticleTitle>` | `<Paragraph>` | `<SupplNote>`）。
`xml_chunking` は22行目で見出しを引数で渡しているので、条の見出しは項のチャンクに
残る。付記（`SupplNote`）は渡していない。

項は事情が違う。**項は自分で本文（柱書）を持っているので、見出しに相当するものを
渡すだけでは足りない。** 降りるときに親の文脈を運ぶ仕組みを、条のレベルでは作って
項のレベルでは作っていなかった。

### 号より下では落ちない

号が閾値を超えたとき、コードは号細分に降りず `split_by_threshold` で号の全文を文字で
切る。号の中の文も号細分も同じ文字列の中にあるため、落ちるものは無い。
**落ちるのは「親から取るのをやめて子から個別に取る」切り替えが起きる箇所だけで、
それは項から号への1箇所である。**

### 検索の指標では気づけない

`Recall` と `Hit` は `article_num` のメタデータで当たり外れを判定している。
**本文が欠けたチャンクでも、引ければ正解として数えられる。** そのため指標を見ても
欠落に気づけない。

## Decision Drivers

* 号のチャンクが単体で意味を持つこと
* **同じ号が、閾値を超えるかどうかだけで持っている文脈を変えないこと。** それは
  今回の欠落と同じ形の不整合である
* 同じ文を二重に前置しないこと
* 既存の挙動と揃えること。閾値の判定を前置きの前に行う形は修正前から Paragraph と
  Item のチャンクでそうなっていた
* 実装の変更を小さく保つ

## Considered Options

1. **号のチャンクに条見出しと項の柱書を前置する**
2. 柱書だけを独立したチャンクにする
3. 号の句点分割では条見出しだけを足す

## Decision Outcome

Chosen option: **「号のチャンクに条見出しと項の柱書を前置する」**（選択肢1）

句点分割では、分割後の各断片に前置きを足す。号を持たない項には柱書を前置しない。
`extract_text(paragraph)` に柱書が含まれており、足すと二重になる。

```
号のチャンク           条見出し ＋ 柱書 ＋ 号
号の句点分割の各断片    条見出し ＋ 柱書 ＋ 断片
号なし項の各断片        条見出し ＋ 断片（柱書は本文に入っている）
```

前置きは閾値の判定より後に足すため、チャンクの長さは最大で閾値＋前置きになる。

### 柱書だけを独立したチャンクにしない（選択肢2を却下）

重複は増えないが、**号を引いたときに柱書が付いてこない。** LLMに渡る文脈は欠けた
ままになるため、解決にならない。

### 号の句点分割で条見出しだけにしない（選択肢3を却下）

柱書を足さないと、**同じ号が、閾値を超えるかどうかだけで持っている文脈が変わる。**
閾値以内の号には柱書が付き、超えた号の断片には付かないことになる。これは今回の
欠落と同じ形の不整合である。

**号を持たない項の句点分割で条見出しだけを足すのは、これとは別である。** 柱書は
`extract_text(paragraph)` に入っているため、足すと二重になる。

### 修正後のチャンク数

現行版のチャンク数は 706,075 から 705,949 になった。

```
Article / Paragraph / Item   1件も動かない
Split                        126件減った
```

`split_by_threshold` に渡すテキストが前置きのぶん短くなったため、断片が減った。
**柱書は分割した後に足しているので、断片の数には影響しない。**

## Consequences

* Good: **号のチャンクが単体で意味を持つようになった。** 柱書が無いと、号だけでは
  列挙されたものがどう扱われるのか決まらなかった
* Good: **条を持たない法令・附則でも柱書が入る。** この経路では `article_heading` が
  空文字だが、柱書は `paragraph` から取るため効く
* Good: **`xml_chunking` の docstring にあった「分割後のチャンクにも見出しが残るように
  する」が、実装と一致した。** 意図は書かれていたが、項から号に降りる経路には
  届いていなかった
* Good: **閾値の判定に前置きが混ざっていないことを、チャンク数の内訳で確認できた。**
  `Article` / `Paragraph` / `Item` が1件も動かず、Split だけが減った
* Bad: **README に掲載している測定は、すべて修正前のコーパスで行ったものである。**
  チャンクの本文が欠けた状態で測った数字が残っている
* Bad: **保存済みのコレクション `ruri-v3-310m_1000_20261013_50055_prefixed` も修正前の
  ままである。** この修正以降にインデックスを作り直すと、README の数字と中身が
  食い違う
* Bad: **欠落していた件数を測っていない。** 影響の大きさは、落ちる条件（号を持つ項が
  閾値を超えたとき）という構造でしか示していない
* Bad: **柱書を兄弟チャンクに複製するため、同じ質問に対して兄弟同士が競合しやすく
  なる可能性がある。** 測っていない
* Bad: **`SupplNote`（付記）は未対応。** 条が閾値を超えて項に降りるときに拾っていない。
  付記を持つ条152件のうち落ちるのは22件で、中身は罰則への参照だった。付記は条の末尾に
  付くため、条見出しのように前置する形が使えない
