# ADR-0020: 条番号の内部表記を出典表示用に変換する

## Context and Problem Statement

`Article` 要素の `Num` 属性は、条番号を機械可読な形式で保持している。
実データを調査したところ、通常の数値以外に2つの表記パターンが存在した。

| 表記 | 出現例 | 想定される意味 |
|---|---|---|
| `88_10` | 建築基準法ほか | 第88条の10 |
| `16:18` | 租税特別措置法 | 第16条から第18条まで |

コロン表記は、租税特別措置法のバージョン比較において
削除・追加された条の中に複数観測された（`15:18`、`48:52`、`49:52`）。
連続する条をまとめて表す形式と推測されるが、
法令標準XMLスキーマの解説では確認できていない。

本プロダクトは根拠となる条文を出典つきで提示することを中核とするため、
「第88_10条」「第16:18条」という表示は許容できない。

## Decision Drivers

* 出典表示は法令の標準的な引用形式に従う必要がある
* 内部処理では機械可読な元の値を保持したい
* 未確認の表記パターンが他に存在する可能性がある

## Considered Options

1. `Num` の値をそのまま表示する
2. 表示時に変換し、内部では元の値を保持する
3. パース時に変換した値のみを保持する

## Decision Outcome

Chosen option: "表示時に変換し、内部では元の値を保持する", because
選択肢1は出典として成立しない。

選択肢3では、変換規則に誤りがあった場合に元の値へ戻せない。
また条番号による検索や、バージョン間の条の突合に元の値が必要である。

選択肢2であれば、突合には元の値を用い、表示時のみ変換できる。
変換規則を後から修正することも可能である。

変換規則:

* `88_10` → 第88条の10（アンダースコア区切りを「の」で連結）
* `16:18` → 第16条から第18条まで

**未確認の表記パターンが存在する可能性があるため、本ADRは proposed とする。**
`Num` 属性の全値を対象に、数値・アンダースコア・コロン以外の
文字を含むものが存在するかを調査し、その結果を踏まえて accepted に更新する。

### Consequences

* Good: 出典表示が法令の標準的な引用形式に従う
* Good: バージョン間の条の突合に元の値を使える
* Bad: 変換処理を表示側に持つため、表示箇所が増えるたびに適用漏れのリスクがある
  → 変換を関数として一箇所にまとめる
* Bad: コロン表記の意味が推測にとどまっている。
  誤った変換をした場合、出典として誤った条を示すことになる
  → 調査で裏付けを取るまで proposed のままとする
