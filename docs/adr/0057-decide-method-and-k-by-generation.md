# ADR-0057: 生成の人手判定で、検索方式と渡す件数を決める

## Context and Problem Statement

ADR-0056 で閾値を500に決めたが、**方式と渡す件数は決められずに保留になった**
（ADR-0056 の Bad に記録した）。閾値1000では素のベクトル検索の `Hit@10` が
0.900（36問）で落ちていたが、閾値500では 0.950（38問）になり、
ADR-0054 の最初のふるい（`Hit`）で落とせなくなったためである。

残った2構成は、条文型40問で `Hit` が同値だった。

| 構成 | Hit | MRR | Recall | 検索時間 | 本文の上限 |
|---|---:|---:|---:|---:|---:|
| ベクトルのみ・10件 | 0.950（38問） | 0.8046 | **0.9250** | **17.2ms** | 5,000字 |
| ハイブリッド＋リランキング・5件 | 0.950（38問） | **0.8646** | 0.8750 | 2,138.1ms | **2,500字** |

状況型5問では `Hit` 1.0 と `Recall` 0.4667 が同値で、`MRR` だけが 1.0000 対 0.9000
で素のベクトル検索が上だった。

**`Recall` と `MRR` が逆を向くため、検索の指標では決着しない。** ADR-0056 の末尾に
「どちらを採るかは `Recall` と `MRR` のどちらを重く見るかで決まり、それは生成で
測るまで決められない」と書いた。本ADRはそれを測った記録である。

## Decision Drivers

* **生成の判定で決める。** 検索の指標では決着しないことが ADR-0056 で確定している
* 判定は ADR-0046 と同じ ○ / △ / × / 創作 / 棄権 の5区分を使う
* 評価セットは ADR-0036 で凍結した50問をそのまま使う
* **変えるのは検索方式と渡す件数だけにする。** モデル・生成パラメータ・seed・
  システムプロンプト・コーパス（閾値500・前置あり）は両構成で同じ

## Considered Options

1. **ハイブリッド＋リランキング・5件**（現状の実装）
2. ベクトルのみ・10件

## Decision Outcome

Chosen option: **ハイブリッド＋リランキング・5件**（選択肢1）

実装は変えない。`config.RETRIEVAL_METHOD = 'hybrid-rerank'`、
`config.GENERATION_K = 5` のままである。

### 判定の基準に2つ足した

* **誤棄権（可答の質問に「答えられない」と述べた場合）は ×** とする。
  今回の測定では両構成とも0件だった
* **渡した条文に書いていなくても、述べている内容が法律として正しければ減点しない。**
  判定の理由にするのは、条番号・項番号・号番号の誤り、内容が法律として誤っている
  こと、聞かれた範囲の外の条を並べたことに限る

### 50問の判定結果

1問ずつ、回答に挙げられた条番号と、その構成に渡したチャンクの条文を読み合わせた。
記録は `evaluation/results/human_generate_compare_vector10_hybrid-rerank5_20261126.csv`
に1問1行で残している。

| 判定 | ベクトルのみ・10件 | ハイブリッド＋リランキング・5件 |
|---|---:|---:|
| ○ 条番号・内容ともに正しい | 12 | **14** |
| △ 内容は正しいが項番号の誤り等 | 12 | **16** |
| × 実在の条文だが結論か根拠が誤り | 21 | **13** |
| 創作 条文に無い内容を根拠にした | **1** | 3 |
| 棄権 答えられないと述べた | 4 | 4 |

問題ごとに比べると、ハイブリッド＋リランキング・5件が上が16問、
ベクトルのみ・10件が上が10問、同じが24問である。

**○ が2件多く、× が8件少ない。** ADR-0046 の5区分で数えて、採用した構成が勝った。

### 種別で差が出る場所が偏っている

| category | ベクトルのみ・10件 | ハイブリッド＋リランキング・5件 |
|---|---|---|
| `fact`（10問） | ○4 △3 ×3 | ○3 △3 ×3 創作1 |
| `number`（5問） | ○3 △2 | ○4 △1 |
| `negation`（5問） | ○1 △1 ×3 | ○3 △2 |
| `comparison`（5問） | ○1 △2 ×2 | ○1 ×3 創作1 |
| `multi_doc`（5問） | ○2 ×3 | ○2 △1 ×2 |
| `long`（5問） | ○1 △1 ×3 | ○1 △3 ×1 |
| `summary`（5問） | △2 ×3 | △4 ×1 |
| `situation`（5問） | △1 ×4 | △2 ×3 |
| `unanswerable`（5問） | 創作1 棄権4 | 創作1 棄権4 |

**`negation` で ○ が 3対1 で分かれた。** 5問のうち、否定が「ただし書」や「を除き」
として文の途中にある3問は、すべて ハイブリッド＋リランキング 5件が上だった。否定が条見出しに出ている
1問（「適用の除外」）は両方とも ○ である。

**`summary` でも ハイブリッド＋リランキング 5件が上である**（△ 4対2、× 1対3）。
**`fact` では ○ が 4対3 で10件の側が上**だが、10件の側は `fact` で創作0件、
5件の側が1件である。

### 検索の `Recall` が高いほうが負けた

ベクトルのみ・10件は条文型 `Recall@10` が 0.9250 で、採用した構成の
`Recall@5` 0.8750 より高い。**根拠の条文がより多くプロンプトに入っていたが、
生成の判定では ○ が2件少なく × が8件多かった。**

ADR-0056 では「根拠が欠けると答えが実質的に間違う例」（ADR-0046 の ts009）を
挙げて `Recall` を優先する理屈を立てたが、**今回の測定ではその向きに出なかった。**
理由は特定していない。

## Consequences

* Good: **ADR-0054 の保留が閉じた。** 閾値は ADR-0056、方式と渡す件数は本ADRで
  決まり、ADR-0054 の決定はすべて置き換わった
* Good: **検索の指標で決着しなかったものが、生成の判定で決着した。** `Hit` が
  同値で `Recall` と `MRR` が逆を向く状態から、○ と × の差で選べた
* Good: **実装を変えずに済んだ。** 現在の `hybrid-rerank` / 5件のまま、根拠が
  付いた状態になった
* Good: **否定の読み落としがどこで起きるかが分かった。** `negation` 5問のうち、
  否定が文の途中のただし書や「を除き」にある3問で判定が分かれ、条見出しに
  「適用の除外」と出ている1問では両方とも正しく答えた
* Good: **判定の基準が2つ増えた。** 誤棄権の扱いと、「渡した条文に無い」と
  「誤っている」の切り分けを、実例に当たってから決めた
* Bad: **創作は、採用した側のほうが多い。** 可答45問で、ベクトルのみ・10件が
  0件、ハイブリッド＋リランキング・5件が2件だった（不可答の1問は両方とも創作）。
  **創作は最も重い区分なので、○ と × で勝ったことだけで優劣を言い切れない**
* Bad: **seed を固定した1標本で、再測定していない。** 同じ構成でもう一度回した
  ときに判定が変わるかを確認していない
* Bad: **判定者が1人で、どちらの構成かが見えている。** 盲検にしていない。
  ADR-0046 と同じ制約である
* Bad: **参照をたどる仕組みが無いことが、4問で効いた。** 参照元の条は渡って
  いるのに参照先が渡っておらず、「同条に定める要件」「第七十四条第二項に規定する
  基準」をたどれずに答えが欠けた。ADR-0046 で検討段階と書いた Graph RAG の動機に
  当たるが、本ADRでは何も決めていない
* Bad: **生成モデルは `Qwen3-8B` の1つだけである。** 別のモデルで同じ順位に
  なるかは測っていない
