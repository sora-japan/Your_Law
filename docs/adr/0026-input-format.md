# ADR-0026: 自由入力で状況を受け取り、確認事項は選択式で提示する

## Context and Problem Statement

想定ユーザーは、新規事業を立ち上げるにあたって法律が気になり始めた事業者である。
困っているのは「何を調べればいいか分からない」「抜けがないか確信が持てない」ことであり、
欲しいのは関係しそうな法令とその根拠である。

ユーザーは最初、「介護の事業所を開きたい」程度の情報しか提示しない。
しかし関係法令を絞り込むには追加の情報が必要になる。

* 業種の細分（同じ飲食業でも、酒類提供・深夜営業・テイクアウトで変わる）
* 規模（従業員数により労働関係法令の適用が変わる）
* 立地・建物（用途地域、構造）

つまり不足情報の確認が必要である。

一方、会話形式で自由に往復する設計にすると、
聞き返しの内容も回答も毎回変わるため、**評価の正解を固定できない**。

## Decision Drivers

* ユーザーが自分の業種や事業区分を正確に言語化できるとは限らないこと
* 聞くべき事項の聞き漏らしが起きないこと
* 評価データの正解を固定できること
* 残り期間が短いこと

## Considered Options

1. 1往復に限定する（状況を書く → 回答）
2. LLM が聞き返しを生成する（2往復で固定）
3. 何往復でも自由に会話できる
4. 業種などをすべて選択式で入力させる
5. 自由入力で状況を受け取り、確認事項を選択式で提示する

## Decision Outcome

Chosen option: "自由入力で状況を受け取り、確認事項を選択式で提示する", because
選択肢3は実装と評価の双方が期間内に収まらない。

選択肢4（すべて選択式）は確実だが、**選択肢にないものを表現できない**。
本プロダクトの想定ユーザーは自分がどの事業区分に当たるかを
把握していない段階にあり、「分かっている人向け」の設計になってしまう。
また、聞くべき項目を網羅した選択肢を用意できるのであれば、
そもそも法令との対応表も作れることになり、LLM を用いる必然性が薄れる。

選択肢2（LLM が聞き返しを生成）は自然だが、
聞き返しの内容が毎回変わるため評価が不安定になり、
かつ聞くべき事項を聞き漏らす可能性がある。

選択肢5であれば、自由入力により「自分が何業か分かっていない人」も受け付けつつ、
確認事項を選択肢として提示することで聞き漏らしを防げる。

**評価はユーザーの状況が確定した時点で行う。**
評価データは「確定した状況 → 正解の法令集合」のペアとして作成する。
入力の集め方（自由入力か選択式か）は評価設計に影響しない構造とする。

確認事項の選択肢の生成方法は本ADRの範囲外とし、別途決定する。
共通項目を固定とするか、入力内容に応じて生成するかは未確定である。

### Consequences

* Good: ユーザーが事業区分を把握していなくても入力できる
* Good: 聞くべき事項の聞き漏らしが起きない
* Good: 評価の正解を固定できる
* Good: 入力方式の変更が評価設計に影響しない
* Bad: 確認事項の選択肢をどう用意するかが未決定であり、別途設計が必要
* Bad: 「会話形式で知りたい」という当初の要望からは後退している。
  対話的な体験は限定的になる
* Bad: 選択肢を固定にすると、業種によっては無関係な質問が混ざる
