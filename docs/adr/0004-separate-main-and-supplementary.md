# ADR-0004: 本則（`MainProvision`）と附則（`SupplProvision`）を分離して保持する

## Context and Problem Statement

法令XMLには本則と附則の両方が含まれる。附則には施行期日、経過措置、
改正に伴う調整規定などが記載され、本則の条文とは性質が異なる。

全法令における `Article` の出現数は1,124,588件だが、
`MainProvision` 配下に限ると551,320件であった。
差の約57万件は附則の中にある。附則は361,881件存在する。

## Decision Drivers

* 「この条文が自分に適用されるか」という問いに対し、附則の施行期日規定は直接の答えにならない
* 一方で附則には施行日や経過措置という、改正検知に必要な情報が含まれる
* 附則の条は本則の条と条番号が重複しうる（どちらにも「第一条」が存在する）

## Considered Options

1. 本則のみをチャンク化し、附則を捨てる
2. 本則と附則を区別せず、まとめてチャンク化する
3. 本則と附則を別々にチャンク化し、メタデータで区別する

## Decision Outcome

Chosen option: "本則と附則を別々にチャンク化し、メタデータで区別する", because
附則を捨てると施行期日や経過措置の情報が失われ、改正検知という主機能に支障が出る。
一方で区別せずに混在させると、条番号が重複して出典の特定が曖昧になり、
検索結果に施行期日規定が混ざって回答の質を下げる。

チャンクに「本則 / 附則」のフラグを持たせ、
附則側には `SupplProvision` の `AmendLawNum`（改正法令番号）も保持する。

### Consequences

* Good: 検索時に本則のみに絞る、附則のみに絞るといった制御ができる
* Good: 出典表示で「本則第◯条」「附則第◯条」を正しく区別できる
* Good: 附則の `AmendLawNum` を保持することで、どの改正で入った規定か追跡できる
* Bad: チャンクの生成処理が本則用と附則用で分岐し、実装が増える
* Bad: 附則が361,881件と多く、全件をチャンク化すると検索対象が大きく膨らむ
  → 附則をインデックス対象に含めるかは、チャンク設計時に再検討する
