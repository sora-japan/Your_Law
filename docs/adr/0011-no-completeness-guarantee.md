# ADR-0011: 関係法令の網羅性を保証せず、再現率を実測して限界を提示する

## Context and Problem Statement

本プロダクトは「自分・自社にどの法律が関係するか」を判定して提示する。
この種の問いに対しては「関係する法令をすべて挙げる」ことが理想だが、
実際に網羅できるかを検討したところ、複数の技術的な制約が存在することが分かった。

**現時点で判明している、網羅を妨げる要因:**

| 要因 | 規模・根拠 |
|---|---|
| 別記様式・別表をスコープ外とした | `Fig` 41,897件が外部PDF参照。別表の数値基準を参照できない（ADR-0008） |
| 本則が抄録の法令が存在する | 292件。収録されていない条文がある（ADR-0006） |
| 表のテキスト化が未解決 | `TableColumn` 353万要素。表に記載された適用範囲を拾えない可能性 |
| 法令間参照を辿っていない | 「法第二条第一項」「令和三年法律第四十号」等の参照先を解決していない |
| ベクトル検索に原理的な限界がある | 類似度上位N件を返す方式である以上、再現率は100%にならない |
| 対象が国の法令に限られる | 条例・規則・ガイドライン・業界自主規制は対象外 |

加えて、漏れが実害に直結する領域である。「関係ないと言われたので対応しなかった」
という使われ方をした場合、利用者に不利益が生じる。

## Decision Drivers

* 提示できない情報がある以上、できないことを事実として明示すること
* 利用者が本プロダクトの出力を最終判断に用いないよう促すこと
* 限界を主観的な但し書きではなく、測定可能な数値として示すこと

## Considered Options

1. 網羅的に提示することを目標とし、達成度は明示しない
2. 網羅性を保証しないと明示するのみで、達成度は示さない
3. 網羅性を保証しないと明示し、評価データに対する再現率を測定して公開する

## Decision Outcome

Chosen option: "網羅性を保証しないと明示し、評価データに対する再現率を測定して公開する", because
選択肢1は、上記の制約がある以上、実現できない目標を掲げることになる。
利用者が「すべて挙がっている」と誤認した場合の不利益が大きい。

選択肢2は誠実ではあるが、「どの程度網羅できているのか」が利用者にも開発者にも分からない。
「保証しない」という文言だけでは、精度が高いのか低いのかの判断材料にならない。

選択肢3は、限界を認めたうえで、その限界を数値として示す。
評価データ（質問と、引けているべき法令・条文の正解ペア）に対する再現率を測定し、
README および出力の注記で提示する。

**本プロダクトの出力は、検討すべき論点への気づきを与えるものであり、
法令調査の完了を意味しない。** この位置づけを README と出力の両方に明記する。

再現率の測定方法・評価データの設計は、評価設計（第2週）で別途定める。

### Consequences

* Good: 提示できる範囲と提示できない範囲が、利用者に対して明確になる
* Good: 再現率という数値があることで、改善の効果を測定できる
* Good: 網羅を目標にしないことで、実現不可能な要件に開発時間を費やさずに済む
* Good: 各スコープ判断（ADR-0006 / 0008 等）の影響を、再現率という共通の指標で評価できる
* Bad: 「すべて教えてくれるツール」を期待する利用者にとっては期待外れになる
* Bad: 再現率の測定には正解データの作成が必要で、その正解は作成者の判断に依存する
  → 評価データの作成基準を記録し、限界も併記する
* Bad: 再現率が低い結果になった場合、それを公開することになる
  → 数値を隠さないことを前提とする。低い値もプロダクトの現状として記録する
