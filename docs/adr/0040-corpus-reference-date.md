# ADR-0040: コーパスの基準日を引数で受け取り、比較実験では固定する

## Context and Problem Statement

ADR-0015 で「現行版は**施行日 ≤ 今日**のうち最新」と定めた。この判定が
`find_current_version_paths` の内部で `datetime.now()` を呼ぶ形で実装されて
いたため、**コーパスの内容が実行した日に依存していた。**

```python
today = datetime.now(ZoneInfo('Asia/Tokyo')).strftime('%Y%m%d')
if enforce_date > today:
    continue
```

一括DLには施行日が2026年のファイルが2,650件ある。日が進むと施行日が到来し、
その法令の現行版が別の版に切り替わる。

### 発見の経緯

`eval_data.py` を切り出すリファクタリング（ADR-0038）の後、挙動が変わって
いないことを確認するために `verify_sub_chunks.py` を走らせたところ、
2026-10-13 の実測と数字が食い違った。

| 項目 | 10/13 | 10/18 |
|---|---|---|
| 全チャンク数 | 706,075 | **706,129**（+54） |

リファクタリングを疑ったが、**基準日を 20261013 に固定して同じコードを
走らせると 706,075 に戻った。** コードは無罪で、原因は日付だと確定した。

5日間で、少なくとも複数の法令の現行版が切り替わっていたことになる。

### 日付依存は2箇所にあった

| 箇所 | 何が変わるか |
|---|---|
| `find_current_version_paths` | **どのファイルを読むか**（現行版の選択） |
| `get_chunks_with_meta` | **`is_current` の値**（チャンクのメタデータ） |

2つ目は見落としやすい。`is_current` は `db.py` の `REQUIRED_KEYS` に含まれる
ため全チャンクのメタデータに入り、Chroma に保存される。

そして **`chunk_id` は `is_current` を含まない**（`law_revision_id#連番`、
ADR-0031）。ADR-0033 で行った「`chunk_id` の並びを `diff` で突き合わせる」
という再現性の検証では、**この依存を検出できない。** 件数の一致も中身の一致を
意味しない。検証が見ていない場所に残っていた。

## Decision Drivers

* 比較実験が成立する条件は「変えていない部分が変わらないこと」である
  （ADR-0032、ADR-0033）。日をまたいだ実験で前日の数値と比較できなくなる
* **本番と実験で正しい挙動が逆である。** 利用者に現行法を見せる本番では
  「今日」が正しく、比較実験では「固定」が正しい
* 渡し忘れた経路が静かに今日を使うことを防ぎたい

## Considered Options

1. 関数の内部で `datetime.now()` を呼ぶ（現状）
2. **基準日を引数で受け取り、呼び出し側が決める**
3. 関数の内部で `config` から基準日を読む
4. 引数で受け取るが、デフォルト値を今日の日付にする

## Decision Outcome

Chosen option: **「基準日を引数で受け取り、呼び出し側が決める」**

```python
def find_current_version_paths(xml_dir: pathlib.Path, reference_date: str) -> list[pathlib.Path]
def get_chunks_with_meta(path: pathlib.Path, chunk_threshold: int, reference_date: str) -> list[dict]
def load_current_chunks(xml_dir: pathlib.Path, chunk_threshold: int, reference_date: str) -> list[dict]
```

```python
# config.py
# どの時点で施行済みの版を「現行版」とするかの基準日。
# 比較実験の間コーパスを固定するために定数にしている（ADR-0040）。
# 本番（利用フェーズ）では今日の日付を渡す。
REFERENCE_DATE = '20261013'
```

**同じ関数で「実験は固定日」「本番は今日」を扱える。** 呼び出し側が値を
決めるだけで、シグネチャは変わらない。

選択肢3を採らないのは、関数の内部で `config` を読むと呼び出し側から日付を
変えられなくなり、本番と実験を分けられないためである。`chunk_threshold` を
`config` から読まずに引数で受けているのと同じ理由（ADR-0022）。

### デフォルト値は付けない

選択肢4を却下した。`reference_date='today'` のようなデフォルトがあると、
**渡し忘れた経路が静かに今日を使う。** 今回の問題がそのまま再発する形になる。
引数を必須にすれば `TypeError: missing 1 required positional argument` で
止まる。

### 本番用のヘルパーは作らない

「今日の日付を返す関数」を用意したくなるが、**呼ぶ側（API）がまだ存在しない。**
作れば使われない関数が1つ増える。

このリファクタリング中に未使用の import / 変数が4件見つかっており
（ADR-0038）、意図的に5件目を作る理由がない。API を実装するときにその場で
足す。設計の意図はこのADRに残す。

### `is_current` は現状の経路では常に True

`find_current_version_paths` が「施行日 ≤ 基準日」で絞った後に
`get_chunks_with_meta` が同じ条件を評価するため、**構造上 False に
なりえない。** 実測で確認した（2026-10-19、基準日 20261013）。

```
is_currentの内訳: Counter({True: 706075})
```

ADR-0017 の「未施行版は現行版との差分だけインデックスする」を実装したときに
False が出る予定のフィールドで、現状は定数である。

**削除は今回のスコープ外とした。** `db.py` の `REQUIRED_KEYS` に含まれる
メタデータの契約（ADR-0030）であり、初回のRecallを測る直前にスキーマを
変えるのは影響範囲が広い。

### `is_current` は判断であり、`enforce_date` は事実である

削除を検討する際の論点として記録する。

```
enforce_date = '20271001'   事実。永遠に変わらない
is_current   = False        判断。インデックスを作った時点のもの
```

判断をインデックスに保存すると、**時間の経過で実態と食い違う。**
基準日 20261013 でインデックスを作ると、施行日 20261101 の版は
`is_current = False` で保存される。2026-11-02 になればその版が現行版だが、
インデックスの値は False のまま残る。

`enforce_date` は事実なので腐らない。ADR-0017 の実装時に「`is_current` を
持つか、検索時に `enforce_date` から計算するか」を判断する。

なお `is_current` を計算して Chroma に渡しているのは `build_metadata` であり、
Chroma 側は渡された値を保存するだけで何も判断していない。

## Consequences

* Good: 比較実験の間、コーパスが固定される。日をまたいでも同じ数値が出る
* Good: 本番と実験で異なる挙動を、同じ関数で扱える。分岐が要らない
* Good: 渡し忘れが `TypeError` で止まる。静かに今日を使う経路がない
* Good: 日付依存を、比較実験を回す前に発見できた。実験後に気づいた場合、
  どの数値がどの日のコーパスで測られたか分からない状態に陥っていた
  （ADR-0036 と同じ構造）
* Bad: 呼び出し箇所7つに引数を追加した。設定を増やすたびに同じコストが
  かかる形になっている
* Bad: `REFERENCE_DATE` は手で更新する値であり、更新を忘れると古い日付の
  コーパスで実験を続けることになる。**この固定は「いつ更新すべきか」の
  基準を持たない。** 全件での最終測定の前に、現在の日付へ更新するかを
  判断する必要がある
* Bad: `chunk_id` による再現性の検証では、メタデータの日付依存を検出
  できなかった。**検証は検証した範囲しか保証しない。** メタデータ全体を
  突き合わせる検証は未実装
* Bad: `is_current` が現状の経路で定数であることが分かったが、削除せずに
  残した。使われていないフィールドを意図的に残す判断であり、ADR-0017 の
  実装が延期されるほど、残した理由が薄くなる
