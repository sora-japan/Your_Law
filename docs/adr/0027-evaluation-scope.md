# ADR-0027: 定量評価の対象を、正解が定義できる範囲に限定する

## Context and Problem Statement

本プロダクトの主機能は「状況から関係しそうな法令を提示する」ことである。
これを定量評価するには「質問 → 正解の法令集合」のペアが必要になる。

質問には2つの型がある。

| 型 | 例 | 正解の定義 |
|---|---|---|
| 条文の中身を問う | 「職員の身分証明書の様式は？」 | 該当条文が一意に決まる |
| **状況から関係法令を問う** | 「介護の事業所を開きたい」 | **一意に決まらない** |

後者が本来の用途だが、正解の定義が難しい。
「飲食店なら何法が関係するか」に唯一の正解はなく、
評価データ作成の一般的な注意点としても、
複雑な質問の多くは単一の正解を持たないと指摘されている。

業種から関係法令を引ける公的なデータを探したが、
経済産業省や中小企業庁が公開しているのは**所管する法令の一覧**であり、
業種別の一覧ではない。機械可読な形で揃っているものは確認できなかった。

一方、介護事業については行政が関係法令を明示している例がある。

> 介護保険事業者の指定を受けるためには、介護保険法だけでなく
> 関係法令（建築基準法、都市計画法、消防法、食品衛生法等）の基準を
> 満たしていることが必要（埼玉県 新規指定申請ページ）

同趣旨の記載が兵庫県・名古屋市・茨城県にも存在する。
ただし「等」とあり、網羅的な一覧ではない。

## Decision Drivers

* 自分で決めた正解で測った数値には意味がないこと
* 評価できないものを測ったふりをしないこと（ADR-0011 と同じ姿勢）
* 出所の明確な正解データを用いること
* 残り期間が短いこと

## Considered Options

1. 状況型の正解を自分で定義して評価する
2. 条文の中身を問う型のみで評価し、状況型は評価しない
3. 条文型を中心に評価し、状況型は行政資料を出所とする限定的な評価を行う

## Decision Outcome

Chosen option: "条文型を中心に評価し、状況型は行政資料を出所とする限定的な評価を行う", because
選択肢1では、正解そのものの妥当性が担保されない。
法律の専門家でない作成者が定義した正解で再現率を出しても、数値に意味がない。

選択肢2は安全だが、本来の用途をまったく評価しないことになる。

選択肢3であれば、介護事業の開業という一領域に限り、
**行政が公開している記載**を出所とした正解を用いることができる。

状況型の正解は「網羅的な一覧」ではなく
**「最低限含まれていなければならない法令の集合」**として扱う。
網羅性を測るのではなく、必須の法令を取りこぼしていないかを測る。
これは ADR-0011（網羅性を保証せず、再現率で限界を示す）と整合する。

正解は法令レベルで与えられ、チャンクは条レベルである。
したがって指標は「**必要とされる各法令から、上位 k 件に最低1チャンクが入っているか**」とする。

**プロダクトのスコープ（コーパス＝全法令）は絞らない。**
絞るのは評価の範囲のみであり、README に
「評価は介護事業の開業という一領域で実施した。他領域への一般化は検証していない」
と明記する。

評価データの規模は30問程度とする。
出所の明確な小さいセットのほうが、確認していない大量のデータより価値があるとされており、
残り期間の制約とも整合する。

**本ADRは proposed とする。** 評価データの内訳（条文型・略称型・範囲外の比率）、
生成の評価に LLM-as-a-judge を用いるかは未確定である。

### Consequences

* Good: 定量評価に用いる正解の出所がすべて明確になる
* Good: 評価できる範囲とできない範囲を切り分け、限界を明示できる
* Good: 評価データが小規模で済み、全件を人手で確認できる
* Bad: 本来の主機能である状況型の評価が、一領域・限定的なものにとどまる
* Bad: 行政資料の記載は「等」を含み、正解集合が不完全である。
  提示された法令のうち正解集合に含まれないものを、
  誤りと判定することはできない（適合率が測れない）
* Bad: 評価が介護事業に偏るため、他業種での性能は未知のままとなる
* Bad: 評価データは特定時点の法令コーパスに対する判断であり、
  法改正により正解が変わりうる。評価データに `law_revision_id` を記録し、
  コーパスの版と紐づけて管理する必要がある
