# ADR-0052: チャンク閾値の比較。採用値は保留し、200と500を候補から外す

## Context and Problem Statement

`config.py` の `CHUNK_THRESHOLD` は 1000 だが、**採用値を決めた記録が無い。** これまで測ったのは 200 と 1000 で、しかも前置（ADR-0050）の前だった。

さらに、閾値を変えると評価コーパスの法令集合が動いていた（ADR-0051）。**比較の土台が揃っていなかったため、過去の測定は並べられない。**

ADR-0051 で法令集合を固定したので、ここで 200 / 500 / 1000 / 2000 を同じ条件で測り直す。

## Decision Drivers

* **`GENERATION_K = 10` は現状の値で、まだ決めていない。** 下げる方向での再測定が残っている。この値のもとでは、上位10件に正解が入るかが生成の必要条件になる
* プロンプトが長くなると生成が遅くなるため、1件あたりの文字数も費用になる
* 閾値を下げると1つの条が複数の断片に割れ、互いに競合することが予想される
* 構築時間とディスクが閾値で変わる

## Considered Options

1. 閾値200
2. 閾値500
3. **閾値1000**（現状）
4. 閾値2000

閾値8000は測っていない。`GENERATION_K = 10` ならプロンプトが最大8万字になり、採用候補にならないためである。**これも件数に依存する判断で、件数を大きく下げれば候補に戻る。** 埋め込み自体には入る（下記）。

## Decision Outcome

**採用値は決めない。** 閾値1000と2000のどちらにするかは、下の Consequences に挙げた未測定の項目が埋まるまで保留する。

* 閾値200と500を採用候補から外す。@1 から @10 まで、どの k でも閾値1000に劣る
* 保留のあいだ `CHUNK_THRESHOLD` は現状の1000のままにする。**これは採用の決定ではなく、設定を動かさないという意味である**

200と500を外す判断は `GENERATION_K = 10` を前提にしている。**この値自体がまだ決まっていない。** 閾値が小さいほど1件あたりの文字数が少ないので、渡す件数を増やす設計にするなら再検討が必要になる。@30 以降でどの閾値もほぼ並ぶことがその根拠になる。

現在検討しているのは `GENERATION_K` を下げる方向である。下げるなら200と500はさらに不利になるため、除外の判断は維持される。**上げる場合にのみ再検討が必要になる。**

### 測定の条件

* 検索方式は hybrid-rerank（ADR-0025 で採用した本番経路）
* 埋め込みに法令名と改正法令番号を前置（ADR-0050）
* 評価コーパスの法令集合を固定（ADR-0051）。gold 6本 + 非gold 671本
* 基準日 20261013
* `EVAL_K_LIST = (1, 3, 5, 10, 20, 30, 50, 100)`
* 4本すべてのコレクションで `check_collection` の検査1〜3が通過

埋め込みモデルの `max_seq_length` と `tokenizer.model_max_length` はどちらも 8192 だった。**閾値2000の文字列も切り捨てられていないので、閾値を上げた効果がそのまま測れている。**

| | 閾値200 | 閾値500 | 閾値1000 | 閾値2000 |
|---|---:|---:|---:|---:|
| 投入チャンク数（評価サブセット） | 97,106 | 64,624 | 50,055 | 42,387 |
| 現行版全法令のチャンク数 | 1,377,065 | 903,544 | 706,075 | 601,299 |
| BM25索引の構築（チャンク取得込み） | 6.2秒 | 5.1秒 | 4.7秒 | 3.7秒 |

最下段は `evaluate_retrieval.py` が出す「チャンクの取得と索引の構築」である。Chroma から全チャンクを取り出す時間と、BM25索引を作る時間の合計で、**埋め込みによるコレクション構築の時間は含まない。**

5問なので、単独では根拠にしない。

### @1 と MRR は1000がピークで、閾値に対して単調ではない

| 閾値 | @1 | MRR |
|---|---:|---:|
| 200 | 0.5375 | 0.6778 |
| 500 | 0.5875 | 0.7325 |
| 1000 | 0.7000 | 0.8314 |
| 2000 | 0.6500 | 0.8068 |

**小さすぎても大きすぎても @1 が落ちる。** 状況型の @1 も 0.2000 / 0.3000 / 0.4000 / 0.3000 で、同じく1000がピークだった。条文型と独立に同じ向きが出ている。

一方 @10 は単調に増える。0.7750 → 0.8500 → 0.8875 → 0.9125。**@1 と @10 で向きが逆になる。**

### 正解チャンクは小さい閾値でも引けている

@30 以降はどの閾値もほぼ並び、@100 では閾値200と500が 0.9875 で閾値1000（0.9750）を上回る。

つまり**正解チャンクは引けていて、上位10件の枠の取り合いで負けている。** 1つの条が複数の断片に割れ、同じ条の断片が10枠を分け合うためと考えられる。

### 1000と2000のトレードオフ

| | 閾値1000 | 閾値2000 | 差 |
|---|---:|---:|---:|
| MRR | 0.8314 | 0.8068 | -0.0246 |
| @1 | 0.7000 | 0.6500 | -0.0500（2問） |
| @10 | 0.8875 | 0.9125 | +0.0250（1問） |

2000を採ると @10 が1問増え、@1 が2問減る。

現状の `GENERATION_K = 10` では @10 が本番の構成に直結する。ただし上位に来た条文はプロンプトの先頭に入るため、MRR が生成の品質に効く可能性もある。**検索の数字だけでは決まらない。**

`GENERATION_K` を下げると @10 ではなく @5 や @3 で比べることになり、そこでは閾値1000と2000の差が縮む（@5 は 0.8750 と 0.8875、@3 は同値）。**件数が決まらないと、どの k を見るべきかも決まらない。**

### 10件で取ってくる文字量が揃っていない

「10件」は揃えているが、10件で取ってくる文字量は揃っていない。閾値が大きいほど1チャンクが長いので、同じ10件でも見ている文字数が違う。

条が割れるたびに条見出しが複製されるので、小さい閾値ほど総文字数が増え、実際の比はこれより小さい。正確な値は、上位10件の `text` の長さを合計して測る必要がある。

## Consequences

* Good: **閾値に最適値があることを4点の測定で確認できた。** @1 と MRR が1000でピークになり、閾値に対して単調な関係ではない。条文型と状況型で向きが一致している
* Good: 200と500を候補から外せたため、**残る比較が1000対2000の2択に絞れた**
* Good: **埋め込みの最大入力長を測定前に確認した。** `max_seq_length` が 8192 なので、閾値2000の結果が切り捨ての影響を受けていないと言える。確認しなければ「長くしても効かない」という誤った結論を書く余地があった
* Good: ADR-0051 で法令集合を固定した状態で測っているため、**4本の測定が同じコーパスに対するものだと言える**
* Bad: **閾値と `GENERATION_K` を独立に決めようとしている。** プロンプト長は両者の積で決まるので、片方が決まらないともう片方も決まらない。そして `GENERATION_K` も生成評価の結果から決まる値なので、先に決めておくこともできない。**両者は生成評価の中で組として決めるしかない。** 本ADRの判断は未確定の件数の上に乗っている。@30 以降でどの閾値もほぼ並ぶことが、両者が独立でないことを示している
* Bad: **上位10件の実際の文字数を測っていない。** 「10件」という条件を揃えただけの比較になっており、1件あたりが長い閾値のほうが構造的に有利である。測れば「同じRecallを何文字で買ったか」という形で比較でき、その文字数はプロンプト長そのものになる
* Bad: **生成で比べていない。** @10 が1問多いことと @1 が2問少ないことのどちらが効くかは、検索指標だけでは決まらない。本来はここで決まる
* Bad: **オーバーラップを実装していない。** 断片化の害が @1 の低下として出ているため、オーバーラップで文脈を補えば小さい閾値の成績が変わる可能性がある
* Bad: **状況型が5問しかない。** カテゴリごとの傾向を単独では主張できず、条文型と向きが一致していることを補強材料として使うにとどまる
* Bad: 偶然の寄与は見積もっていない。閾値が大きいほど総チャンク数が減るので、偶然で正解を引く確率はわずかに上がる。閾値1000と2000では母数が 50,055 と 42,387 なので相対的に18%違うが、絶対値は5万分の1から4万分の1の水準で、測っている 0.9 前後には届かない
