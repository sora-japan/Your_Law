# ADR-0053: 検索方式の採用を保留し、生成に渡す件数と組で決める

## Context and Problem Statement

ADR-0025 でハイブリッド検索 + リランキングを採用し、2026-11-14 に `accepted` に
更新した。その直後に同じ測定を読み返して、**採用の前提が崩れていることに
気づいた。**

前置（ADR-0050）を入れたあとの5方式を同一セッションで測ると、条文型40問の
`Recall@10` で**素のベクトル検索が hybrid-rerank に並ぶ。** リランカーの優位が
k=5 以降で消えている。

### 前置はベクトル検索だけを大きく改善した

前置なしのコレクション `ruri-v3-310m_1000_20261013_50055` で測った値と比べる。
法令集合は同じである（ADR-0051 の検証で `chunk_id` の集合一致を確認済み）。
vector の値は ADR-0025 の 2026-11-05 の追記にあり、hybrid-rerank の値は
README の表（出どころは `retrieval_..._50055_hybrid-rerank_2026110*.jsonl`）にある。

| | 前置なし | 前置あり | 差 |
|---|---:|---:|---:|
| vector @1 | 0.4375 | 0.5875 | +0.1500 |
| vector @10 | 0.7375 | 0.9000 | +0.1625 |
| vector @100 | 0.8875 | 0.9750 | +0.0875 |
| hybrid-rerank @1 | 0.6875 | 0.7000 | +0.0125 |
| hybrid-rerank @10 | 0.8750 | 0.8875 | +0.0125 |

**リランク付きはほとんど変わらず、素のベクトル検索だけが上がった。**

ADR-0050 は重複チャンクの対処として入れたもので、ベクトル検索そのものの改善を
狙ったものではなかった。結果として、**リランカーが埋めていた差の大部分を、
前置が別の手段で埋めた。** 2つは代替関係にあったことになる。

## Decision Drivers

* **k によって最良の方式が変わるため、k を決めずに方式を決められない**
* `GENERATION_K` は生成評価の結果から決まる値であり、先に決めることもできない
  （ADR-0052 と同じ事情）
* リランカーを外すと検索が 2,752.6ms から 26.7ms になり、BM25 索引の構築も
  不要になる
* 検索の指標は生成の代理指標にすぎない。最終的な判断は生成でしかできない

## Considered Options

1. ADR-0025 の採用（ハイブリッド + リランキング）をそのまま維持する
2. 素のベクトル検索に切り替える
3. **採用を保留し、生成評価で k と組で決める**

## Decision Outcome

Chosen option: **「採用を保留し、生成評価で k と組で決める」**

ADR-0025 の `accepted` は取り消さない。実装も現状のまま hybrid-rerank である。
本ADRは**その採用を見直す必要が出たことの記録**であり、生成評価で決着する。

### k が小さいほどリランカーが効き、k=5 で優位が消える

条文型40問で、hybrid-rerank と素のベクトル検索を比べる。

| k | hybrid-rerank | vector | 差 |
|---|---:|---:|---|
| 1 | 0.7000 | 0.5875 | +0.1125（4.5問） |
| 3 | 0.8375 | 0.7750 | +0.0625（2.5問） |
| 5 | 0.8750 | 0.8625 | +0.0125 |
| 10 | 0.8875 | 0.9000 | -0.0125 |
| 20 | 0.9375 | 0.9500 | -0.0125 |
| 30以降 | 同じ | 同じ | 0 |

**k=1 と k=3 では差が大きいが、k=5 以降は 0.0125 しか違わない。**

0.0125 は、**2条 gold の問題の片方1件ぶん**にあたる（1 ÷ 2 ÷ 40）。つまり
k=10 で vector が上に出ているのは1条の有無で決まっており、**「上回った」と
言うには母数が足りない。** 言えるのは「k=5 以降でリランカーの優位が消えた」
までである。

それでも採否には効く。**同等なら 2.7秒を払う理由がない。**

### 何を得て何を失うか

`compare_retrieval.py` で集計した条文型40問の中央値（ミリ秒）。

| 方式 | 検索 | リランク | 合計 | BM25索引の構築 |
|---|---:|---:|---:|---|
| vector | 26.7 | - | 26.7 | 不要 |
| hybrid-rerank | 46.0 | 2,706.6 | 2,752.6 | 4.9秒 |

```
k=10 で素のベクトルにすると   1問あたり約2.7秒、起動時に約4.9秒が消える
                              条文型の Recall は 0.0125 しか変わらない
k=3 で hybrid-rerank なら     条文型で2.5問ぶん多く正解が入る
                              1問あたり2.7秒を払う
```

本番の生成時間は1問あたり中央値 30.05秒（`generation_rag_20261020.jsonl`、
思考モードOFF）なので、2.7秒はその**約9%**にあたる。無視できる量ではない。

ADR-0025 は時間の基準に「生成の TTFO 17.5〜20.9秒」を使っているが、**これは
思考モードONで測った別の測定である。** `llm_params.py` は
`apply_chat_template` に `enable_thinking=False` を渡しておらず、Qwen3 の既定が
True のため思考が走る。思考モードOFFでは `</think>` が出ないので TTFO は
`None` になり、CSVには記録されない。本番の構成と比べるには 30.05秒 を使う。

### 状況型では方式ごとに向きが違う

```
@1 / MRR    素のベクトルが最良（MRR 1.0、@1 は天井の 0.4667）
@10        vector / vector-rerank / hybrid-rerank が同じ 0.5667
@30 / @50   hybrid-rerank が最良（@50 0.8667）
@100       hybrid-rerank / bm25 / hybrid が同値（0.8667）
```

条文型と同じ方式が最良になるとは限らない。**カテゴリごとに別の方式を使う
設計も選択肢に入るが、本プロジェクトでは検討していない。**

## 追記（2026-11-16）: ADR-0054 で hybrid-rerank に決着した

保留していた検索方式は、ADR-0054 で **hybrid-rerank**（現状のまま）に決まった。
生成に渡す件数は5件である。生成評価ではなく、`Hit@k` を指標に加えて検索指標で
決めた。比較と理由は ADR-0054 にある。

本ADRの表の `MRR` 行は、`EVAL_K_LIST` の最大が100なのですべて **MRR@100**
である（ADR-0037 の 2026-11-05 の追記）。ADR-0054 は k=5 で測り直しており、
hybrid-rerank の MRR は本ADRが 0.8314、ADR-0054 が 0.8292 である。


## Consequences

* Good: **採用した直後に、その前提が崩れていることを自分の測定で見つけられた。**
  ADR-0025 を accepted にした翌日に気づいたため、誤った前提のまま生成の評価を
  作り直す手戻りを防げた
* Good: **前置とリランカーが代替関係にあったことが数字で出た。** 前置を入れると
  リランカーの差が @10 でほぼ消える。「改善策を足せば足すほど効く」わけでは
  ないという具体例になる
* Good: **k=10 を続けるなら検索が2.7秒速くなる可能性が見えた。** 本番の生成時間
  （30.05秒）の約9%にあたる
* Good: ADR-0052 で「閾値と `GENERATION_K` は組で決めるしかない」と書いた事情が、
  検索方式にも及んでいることが分かった。**保留すべき対象が1つ増えた**
* Bad: **生成で測っていない。** k ごとの最良の方式は検索指標の上での話で、
  生成の正解率がどう動くかは分からない
* Bad: **k=5 以降の差が 0.0125 しかなく、母数が足りない。** これは2条 gold の
  問題の片方1件ぶんである。「k=10 では素のベクトルが勝つ」とは言えず、
  言えるのは「優位が消えた」までである
* Bad: **決着に必要な測定が増えた。** 閾値（1000 / 2000）× `GENERATION_K`
  （5 / 10）× 検索方式（vector / hybrid-rerank）で8通りになる
* Bad: **状況型5問で方式ごとに向きが違うが、機構を追えていない。** 素のベクトルが
  MRR 1.0 になる理由も、リランカーが上位を悪化させる理由も特定していない
* Bad: **生成の評価が今の検索構成を反映していない。** 人手判定はベクトル検索のみ・
  前置なし（Recall@10 0.7375）の構成で行ったもので、現在の 0.9000 とは別物である。
  どちらがボトルネックかを今の構成で測っていない
