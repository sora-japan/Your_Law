# ADR-0013: 空白正規化で改行・タブ・半角スペースを除去し、全角スペースは保持する

## Context and Problem Statement

法令XMLは整形されて配布されているため、要素間の改行とインデントが
`.text` / `.tail` に含まれる。抽出したテキストをそのまま用いると、
無駄なトークンを消費し、文字数の計測も不正確になる。

一方、空白を一律に除去してよいかを判断するため、
`Column` 要素（71.5万件）を対象に空白の出現状況を調査した。

| 種別 | 件数 |
|---|---|
| 前後に空白あり | 713,493 |
| 内部に半角スペース | 2,362 |
| 内部に改行 | 2,311 |
| 内部に全角スペース | 1,549 |
| 空 | 1,926 |

実データのサンプルを確認したところ、種別ごとに性質が異なることが判明した。

**内部の半角スペース**（2,362件）は、すべて改行直後のインデントであった。
`Sentence` の `Function="main"` と `"proviso"` の境界に現れる。
内部の改行2,311件とほぼ同数なのは、同一現象を別観点から数えているため。

```
...都道府県知事をいう。
                  ただし、第九十七条の二第一項若しくは...
```

**内部の全角スペース**（1,549件）は、数式の記号定義に使われていた。

```
Ｃ　二酸化炭素の濃度（単位　体積百分率）
Ａｈ　測定された水素の濃度（単位　体積百分率）
```

これを除去すると「Ｃ二酸化炭素の濃度（単位体積百分率）」となり、
記号と説明の境界が失われて意味が壊れる。

## Decision Drivers

* 整形由来の空白を除去し、トークン消費と文字数計測の誤差をなくすこと
* 原文で意味を持つ空白を保持すること
* 正規表現の `\s` は全角スペースを含むため、そのままでは使えないこと

## Considered Options

1. すべての空白文字を除去する（`\s` を使用）
2. 空白を一切除去しない
3. 改行・タブ・半角スペースのみ除去し、全角スペースを保持する

## Decision Outcome

Chosen option: "改行・タブ・半角スペースのみ除去し、全角スペースを保持する", because
選択肢1は全角スペース1,549件を巻き込み、数式の記号定義を破壊する。
Python の正規表現では `\s` に全角スペースが含まれるため、
除去対象を明示的に列挙する必要がある。

選択肢2はインデントが残り、埋め込み時に無意味なトークンを消費する。

実装は `re.sub(r'[\n\t ]+', '', text).strip()`。
対象文字を文字クラスで列挙することで、全角スペースを対象外とする。

また、正規化は再帰処理の内部ではなく**呼び出し側で最後に1回だけ**適用する。
再帰の各階層で実行すると同一文字列に対して何度も処理が走るため。

### Consequences

* Good: 整形由来の空白のみが除去され、意味を持つ空白が保持される
* Good: 判断が実データのサンプル確認に基づいており、根拠を提示できる
* Bad: `Sentence` の main / proviso の境界情報が失われ、
  「〜をいう。ただし、〜」と連続する。文の区切りを後から復元できない
  → 必要になった場合は `Function` 属性をメタデータに保持する形で再検討する
* Bad: `\r` `\v` `\f` など列挙外の空白文字が将来出現した場合、除去されない
  → 末尾の `.strip()` が部分的な保険として機能する
