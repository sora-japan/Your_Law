# ADR-0007: 目次（`TOC`）をチャンク化しない

## Context and Problem Statement

法令XMLには `TOC`（目次）要素が3,553件存在し、`TOCChapter`（26,167件）、
`TOCSection`（23,466件）などの子要素で構成される。
目次には章名・節名と、それぞれが含む条の範囲（`ArticleRange`）が記載されている。

目次には構造情報が含まれるため、検索精度の向上に寄与する可能性がある。
一方で条文そのものは含まれない。

## Decision Drivers

* 本プロダクトは「根拠となる条文を出典つきで提示する」ことを中核とする
* 検索結果の上位に、根拠として使えない情報が混ざるのを避けたい
* 章・節という構造情報は判定精度に寄与しうる

## Considered Options

1. 目次を他の要素と同様にチャンク化する
2. 目次をチャンク化せず、構造情報も使わない
3. 目次をチャンク化せず、章・節の情報は本文側の階層から取得してメタデータに保持する

## Decision Outcome

Chosen option: "目次をチャンク化せず、章・節の情報は本文側の階層から取得してメタデータに保持する",
because 目次に含まれる章名・節名は本文側の `ChapterTitle` / `SectionTitle` にも
同一の情報が存在するため、チャンク化すると情報が重複する。
その結果、章名にキーワードが一致した目次チャンクが検索上位に来ても、
条文を含まないため回答の根拠として使えず、検索ノイズとなる。

構造情報が有用であるという点は認めるが、それは目次から取る必要がなく、
本文側で `Chapter` → `ChapterTitle` を辿れば同じ情報がより確実に得られる。

なお「章名をチャンクのテキストに含めると検索精度が上がるか」は
チャンク設計時に比較実験を行い、別途判断する。

### Consequences

* Good: 条文を含まないチャンクが検索結果に混ざらない
* Good: 同一情報の重複インデックスを避けられる
* Good: 章・節情報は構造から取得するため、目次が存在しない法令でも同じ扱いができる
* Bad: 目次に固有の情報（条の範囲表記など）が失われる
* Bad: 本文の階層を辿って章名を取得する処理が必要になり、パーサーの実装が増える
