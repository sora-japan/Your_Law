# ADR-0008: 別記様式・別表をスコープ外とし、参照の存在のみ保持する

## Context and Problem Statement

法令XMLには別記様式（`AppdxStyle` 30,319件）、別表（`AppdxTable` 5,690件）、
図（`Fig` 41,897件）が含まれる。

`Fig` は `<Fig src="./pict/2FH00000082736.pdf"/>` の形式で外部PDFを参照しており、
**中身はXMLに含まれていない**。一括ダウンロードのデータにもPDFは含まれていない。
取得するには API の `/attachment` エンドポイントを別途呼び出す必要がある。

## Decision Drivers

* 開発期間が限られていること
* 本プロダクトの判定対象は「条文の適用可能性」であること
* 利用者が、扱われていない情報の存在を認識できること

## Considered Options

1. `/attachment` から全PDFを取得し、OCRでテキスト化して検索対象に含める
2. 完全に無視する
3. スコープ外とし、参照の存在のみメタデータに保持して回答時に示す

## Decision Outcome

Chosen option: "スコープ外とし、参照の存在のみメタデータに保持して回答時に示す", because
選択肢1は、41,897件のPDFの取得・保存・OCR処理が必要となり、
限られた期間で実装するには規模が大きすぎる。また様式の中身は申請書の書式であり、
「どの法律が自分に関係するか」という判定には直接寄与しない。

選択肢2では、利用者が別記様式の存在に気づけないまま「この条文がすべて」と
誤認するおそれがある。

条のメタデータに「別記様式・別表への参照を含む」というフラグを持たせ、
該当する条を根拠として提示する際にその旨を示す。

### Consequences

* Good: 実装規模を抑えつつ、情報の欠落を利用者に明示できる
* Good: 「答えられる範囲を明示する」という設計思想と一貫する
* Bad: 別表に規定された数値基準など、判定に有用な情報を活用できない
* Bad: 将来スコープに含める場合、OCR処理とPDFの保存基盤が新たに必要になる
