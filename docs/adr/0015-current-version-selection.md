# ADR-0015: 現行版を「施行日が今日以前のうち最新」で特定する

## Context and Problem Statement

e-Gov の法令XML一括ダウンロードには 10,702 ファイルが含まれるが、
ユニークな法令IDは 8,997 であり、差の 1,705 ファイルは同一法令の別バージョンである。

ファイル名は `法令ID_改正法の施行日_改正法の法令ID` の構造を持つ
（出典: ja-law-parser 作者による解説。デジタル庁の公式仕様書ではない）。

どのファイルが「現在有効な条文」なのかを特定する必要があるが、
XML の内部には判定に使える情報がない。3つのバージョンを比較したところ、

* `Law` の属性は公布日のみで、施行日も現行かどうかも含まない
* `LawBody` / `MainProvision` の属性は空
* 最後の附則の `AmendLawNum` は版によらず同一

したがって判定材料はファイル名の施行日のみとなる。

全法令を対象に、施行日が今日（20260915）以前のファイル数を法令IDごとに数えた結果:

| 過去日ファイル数 | 法令数 |
|---|---|
| 0 | 0 |
| 1 | 8,996 |
| 2 | 1 |

過去日を持たない法令は存在せず、ほぼ全法令で施行済みファイルは1つだけであった。
例外は租税特別措置法（`332AC0000000026`）の1件で、`20260401` と `20260812` の2つを持つ。
この2版は本則の条数こそ同じ（496条）だが、内容が異なる条が129条あり、
条の増減も発生している（旧のみ7種・新のみ7種の条番号）。

## Decision Drivers

* 施行済みでない条文を「現在適用されます」と提示しないこと
* 古い版を選んで改正前の条文を提示しないこと
* 8,997法令すべてに対して機械的に適用できる規則であること

## Considered Options

1. XML 内のメタデータで判定する
2. ファイル名の施行日が最も新しいものを選ぶ
3. ファイル名の施行日が今日以前のもののうち、最新を選ぶ

## Decision Outcome

Chosen option: "ファイル名の施行日が今日以前のもののうち、最新を選ぶ", because
選択肢1は、XML 内に判定可能な情報が存在しないため実現できない。

選択肢2は未施行版を選んでしまう。一括ダウンロードには 2030年施行のファイルまで含まれており、
地方税法では33版中32版が未施行であった。単純に最新を取ると、
4年後に施行される条文を「現在の法令」として提示することになる。

選択肢3であれば、施行済みのうち最も新しいものが選ばれる。
過去日が複数ある租税特別措置法でも、`20260812` の版が正しく選ばれ、
`20260401` を選んだ場合に生じる「129条が改正前のまま」という誤りを回避できる。

境界は `施行日 <= 今日` とする。今日ちょうど施行のものは現行版に含める。

### Consequences

* Good: 8,997法令すべてで現行版が一意に特定できる（過去日を持たない法令は0件）
* Good: ファイル名のみで判定でき、パースが不要なため高速
* Good: 未施行版を現行版として提示する誤りを構造的に防げる
* Bad: 判定が「今日の日付」に依存するため、実行日によって結果が変わる
  → 差分更新のたびに再判定する運用が必要
* Bad: ファイル名の構造が公式仕様書で確認できていない。
  e-Gov 側でファイル命名規則が変更された場合、判定が破綻する
  → 現行版の件数が 8,997 から変動した場合に検知できるよう、件数をログに残す
